# LING OS 文档规范

> 版本：v1（2026-10-30）
> 作用：统一文档类型、模板、命名、双语、评审与质量门禁，避免“文档被吞/过期/对不上代码”。

---

## 1. 文档类型与必备清单

| 类型 | 文件名 | 内容 | 何时更新 |
|---|---|---|---|
| 总览 | README.md | 项目定位、快速开始、链接索引 | 功能/入口变化 |
| 架构 | LINGOS-架构-*.md | 分层、模块、数据流 | 架构变更 |
| 接口 | LINGOS-接口契约与错误码规范.md | API/WS/IPC/AI/插件契约 | 接口变更 |
| 安全 | LINGOS-0.10-安全与隐私架构-*.md | 威胁模型、等级、机制 | 安全机制变更 |
| 版本 | LINGOS-版本与功能规范.md | 版本号/edition/矩阵/发布标准 | 每版本 |
| 工程 | LINGOS-工程与工业化规范.md | 流程/质量门禁/测试/发布 | 流程变更 |
| 文档 | LINGOS-文档规范.md | 本文件 | 规范变更 |
| 路线 | LINGOS-功能生命周期与工业化路线.md | 功能流程/未来功能/阶段 | 规划变更 |
| 变更日志 | CHANGELOG.md | Added/Changed/Fixed/Security | 每版本 |
| 升级说明 | LINGOS-升级-<version>.md | 迁移/回滚/已知问题 | 每版本 |
| 测试报告 | LINGOS-测试报告-<version>.md | 用例/结果/证据 | 每版本 |
| 运维手册 | LINGOS-Runbook.md | 故障处理/恢复/日志获取 | 运维变更 |
| ADR | docs/adr/NNNN-*.md | 架构决策记录 | 重大决策时 |
| 安全公告 | SECURITY.md / advisory | 漏洞披露/修复 | 安全事件 |

## 2. 命名与目录

- 文件名：LINGOS-<主题>-<类型>[-<日期>].md；
- 日期格式 YYYYMMDD；
- 版本相关文档放 docs/，ADR 放 docs/adr/；
- 禁止中文文件名用于发布资产（GitHub 会清洗），仅仓库内部文档可用中文名；
- 图片放 docs/assets/，引用相对路径。

---

## 3. 写作规则

1. 先给结论，再给细节；
2. 每节可独立理解，避免“见上文”；
3. 命令/路径/版本必须可复制且校验过；
4. 明确适用范围与版本（“0.10+ 生效”）；
5. 安全/隐私敏感内容标注风险与默认值；
6. 不写无法验证的承诺；不确定处标“待确认”；
7. 中文为主，英文关键术语保留；双语要求见第 5 节。

---

## 4. 模板

### 4.1 ADR 模板
- 标题、状态（提议/接受/废弃）、日期
- 背景与问题
- 可选方案与权衡
- 决策
- 影响（代码/接口/运维/安全/版本）
- 后续动作

### 4.2 接口文档模板
- 用途/鉴权/限流
- 请求字段表（名/类型/必填/说明/示例）
- 响应字段表 + 错误码
- 示例（成功/失败）
- 兼容性与版本

### 4.3 测试报告模板
- 版本/commit/环境
- 用例矩阵（功能/安全/隐私/性能）
- 结果与证据（日志/截图路径）
- 未通过项与风险
- 结论（可发布/阻塞）

### 4.4 升级说明模板
- 影响范围
- 升级步骤
- 配置/数据迁移
- 回滚步骤
- 已知问题

## 5. 双语与一致性

- 对外文档（README、安装指南、用户指南）需中英双语或至少英文摘要；
- 双语内容按段落/键一一对应，禁止只更新一侧；
- CI 可做链接检查与双语章节数量对比（渐进）；
- 历史“双语与文档一致性报告”继续沿用并扩展。

---

## 6. 文档质量门禁

1. 代码变更涉及接口/配置/默认值 → 必须更新对应文档；
2. 新增功能 → 必须有 README/使用说明/测试证据；
3. 安全/隐私变更 → 必须有威胁/隐私说明；
4. 发布 → 必须更新 CHANGELOG + 版本矩阵 + 测试报告；
5. 死链检查通过；
6. 过期文档（与代码不符）视为 bug，优先修复。

---

## 7. 评审与维护

- 文档评审与代码评审同流程；
- 每个模块指定文档负责人；
- 每版本发布前做一次“文档一致性扫描”；
- 文档变更记录在 CHANGELOG 的 Docs 区；
- 重要文档变更需 ADR 或评审记录。

---

## 8. 索引

根目录 docs/README.md 维护全部文档索引（见本次新增）。
