# LING OS 工程与工业化规范

> 版本：v1（2026-10-30）
> 状态：规范基线；等待构建/下载期间编写，未部署
> 目标：让 LING OS 从“能跑的 demo”升级为“可维护、可测试、可发布、可审计、可交接”的工业化系统。

---

## 1. 工业化判定标准（10 条）

1. 每次提交自动构建 + 自动测试，失败不可合并；
2. 制品可复现（同 commit 同工具链 → 同 hash）；
3. 接口有契约（版本化、错误码、兼容策略）；
4. 每个功能有文档、测试、负责人；
5. 发布有检查清单、签名、SBOM、回滚方案；
6. 运行时可观测（日志/指标/追踪/诊断包）；
7. 安全与隐私有威胁模型与评审；
8. 性能与资源有预算并自动回归；
9. 故障有 runbook、事故流程、SLO；
10. 新人/子智能可按文档独立接手模块。

---

## 2. 架构原则

1. 分层：启动层 / 系统服务层 / 接口层 / 应用层 / UI 层，禁止跨层直接依赖。
2. 单一职责：一个进程只做一类事（lingosd 管核心、alertd 管告警、visiond 管视觉等）。
3. 契约优先：跨进程/跨语言一律走版本化接口（HTTP/WS/Unix socket JSON），不共享内部结构体。
4. 配置外置：代码不写死路径/端口/密钥；配置有 schema 与版本。
5. 失败可诊断：每个错误有错误码、上下文、trace_id，日志可定位。
6. 安全默认：最小权限、默认拒绝、密钥不落日志。
7. 可降级：关键链路（桌面/安装/预警）有兜底与恢复路径。
8. 可替换：AI Provider、模型、插件、桌面组件均可替换，不绑死单一实现。

---

## 3. 开发流程（每个变更）

1. Issue / 需求记录（目标、范围、验收）；
2. 需要架构决策时写 ADR（docs/adr/NNNN-*.md）；
3. 写接口/数据变更说明（涉及 API、配置、DB 时）；
4. 分支：feat/<topic>、fix/<topic>、docs/<topic>；
5. 本地/CI 通过质量门禁；
6. PR 模板填写：变更、影响面、测试证据、文档更新、回滚方法；
7. 至少 1 次 Review（涉及安全/隐私/发布需额外评审）；
8. 合并到 main（squash），禁止直接 push main；
9. 按版本规范发布。

---

## 4. 代码规范

### 4.1 通用
- 提交信息：Conventional Commits（feat/fix/docs/refactor/test/build/ci/chore/sec）；
- 一个 PR 只做一件事；大重构拆分；
- 禁止提交密钥、token、内网地址、个人数据；
- 新增依赖必须说明理由、许可证、体积/安全影响。

### 4.2 C
- C11；编译器警告 -Wall -Wextra -Werror（关键模块）；
- 禁止裸 strcpy/sprintf；使用 safe_string；
- 资源获取即初始化，错误路径统一 goto cleanup；
- 对外接口命名 lingos_<module>_<action>；
- 结构体不透明化（头文件不暴露内部字段）。

### 4.3 Python
- Python 3.11+；ruff + black + mypy（渐进）；
- 类型注解覆盖公开函数；异常分类（用户错误/系统错误/外部错误）；
- 禁止裸 print 入生产日志；统一 logging。

### 4.4 Shell
- bash + set -Eeuo pipefail；
- shellcheck 通过；变量加引号；临时文件用 mktemp；
- 幂等、可重入、失败给错误码。

### 4.5 Web/前端
- 原生/轻量优先；无构建链的 WebUI 保持单文件可审计；
- XSS/CSRF 防护；CSP；不内联不可信内容；
- API 调用统一封装、错误统一展示。

---

## 5. 质量门禁（CI 必过）

| 门禁 | 内容 | 阻断 |
|---|---|---|
| 构建 | 双架构编译通过 | 是 |
| 单元测试 | 核心模块覆盖率 ≥ 60%（1.0 前 70%） | 是 |
| 集成/契约测试 | API/IPC/tool 契约用例 | 是 |
| 启动冒烟 | ISO 构建 + QEMU UEFI 启动 + 安装器阶段 PASS | 是 |
| 静态检查 | shellcheck/ruff/clang-tidy/gitleaks | 是 |
| 安全扫描 | 依赖 CVE、密钥扫描、权限检查 | 是 |
| 隐私检查 | 默认无遥测、无外联白名单 | 是 |
| 文档检查 | 变更涉及接口/配置必须更新文档 | 是 |
| 版本检查 | 版本号/edition/命名符合规范 | 是 |

---

## 6. 测试体系

1. 单元测试：C（check/CMocka）、Python（pytest）；
2. 契约测试：HTTP/WS/IPC 请求响应 schema 校验；
3. 集成测试：服务间、AI 工具链、告警链路；
4. 系统测试：QEMU 双架构启动冒烟、安装冒烟、桌面兜底链；
5. 回归测试：历史 bug 用例库（每个 P0/P1 bug 必须有回归用例）；
6. 性能测试：启动时间、内存、API p95、AI 首 token；
7. 安全测试：越权、沙箱逃逸、网络泄漏、FDE、篡改更新；
8. 隐私测试：tcpdump 验证无未授权外联、DNS/WebRTC 泄漏；
9. 兼容测试：升级/回滚、配置迁移、edition 切换。

测试证据：CI 日志 + 截图/串口日志 + 报告文件，随 PR/Release 存档。

---

## 7. CI/CD 流水线

阶段：lint → build → unit → contract → image build（arm64/x86_64）→ boot smoke → security scan → artifact upload → publish（人工/自动触发）。

规则：
- main 保护分支，必需 CI；
- 镜像构建缓存加速但可一键无缓存重建；
- 所有产物带 commit/版本/构建时间元数据；
- 发布只能由 publish 工作流执行；
- 失败自动通知（Issue/通知中心）。

---

## 8. 发布工程

- 版本规范见 docs/LINGOS-版本与功能规范.md；
- 发布前检查清单（见版本规范第 10 节）；
- 签名：0.11 起镜像/更新包签名（minisign/cosign）+ SHA256SUMS；
- SBOM：0.11 起 SPDX/CycloneDX；
- 可复现构建：0.11 起记录工具链、容器镜像、依赖锁定；
- 回滚：保留上一版本，A/B 或镜像回退方案；
- Release 正文：新增/变更/修复/安全/已知问题/升级/回滚；
- 资产命名：LINGOS_<arch>_<version>_<edition>.iso（分片 .partN + .merge.txt）。

---

## 9. 兼容性与弃用

- API 版本：/api/v1；破坏性变更进 v2；
- 配置 schema 带 version + 迁移脚本；
- 弃用：提前一个 MINOR 标记，文档给替代；
- edition/配置变更提供迁移与回滚；
- 1.0 起承诺 API/配置稳定性。

---

## 10. 可观测性

- 日志：JSON lines，字段 time/level/module/event/trace_id/request_id/version，敏感字段脱敏；
- 指标：请求量/延迟/错误率、启动时间、内存、安装阶段耗时、AI 调用；
- 追踪：跨服务 trace_id（HTTP/WS/IPC 传递）；
- 诊断包：lingos-diag 收集日志/配置/DRM/网络/服务状态，一键导出；
- 健康检查：/healthz、/readyz、服务 watchdog。

---

## 11. 安全与隐私工程

- 威胁建模（每版本更新）；
- Secure SDLC：依赖扫描、密钥扫描、代码审计；
- 安全评审触发条件：认证/权限/加密/网络/更新/沙箱/AI 工具；
- 隐私评审触发条件：采集/上报/位置/生物特征/云端 AI；
- 漏洞披露流程（security.txt、响应时限、CVE 流程）；
- 供应链：锁定依赖、镜像校验、构建隔离。

## 12. 性能与资源预算（初始）

| 指标 | 目标 |
|---|---|
| 低端 arm64 桌面可用 | ≤ 20s（TCG 环境另算，需标注） |
| 安装耗时 | 参考硬件 ≤ 10 分钟 |
| lingosd 内存 | ≤ 80MB |
| WebUI 首屏 | ≤ 2s（局域网） |
| API p95 | ≤ 200ms（本地） |
| AI 首 token（本地） | 视模型，记录基线 |
| ISO 体积 | server ≤1.2GB / desktop ≤2.5GB / system ≤3.5GB |

预算变更需在 PR 说明原因并更新本表。

## 13. 文档要求

- 每个模块必须有：README（用途/接口/配置/示例/故障排查）；
- 每个对外接口必须有契约文档；
- 每个版本必须有 CHANGELOG、升级说明、测试报告；
- 每项安全/隐私功能必须有威胁/隐私说明；
- 文档随代码评审，过期文档视为 bug；
- 文档规范见 docs/LINGOS-文档规范.md。

---

## 14. 运维与支持

- SLO（1.0 前定义）：桌面可用性 ≥ 99%、告警链路成功率 ≥ 99.9%、API 错误率 < 1%；
- 事故等级与响应流程；
- Runbook：安装失败、桌面起不来、告警失败、更新失败、磁盘满、网络异常；
- 备份/恢复手册；
- 用户支持入口与日志获取指南。

---

## 15. 团队与子智能协作

- Lead：架构、核心代码、发布、验收；
- 子智能：CI 轮询、下载校验、文档比对、测试执行、镜像探测；
- 共享任务板：任务、写范围、依赖、验收标准；
- 交接：分支 + PR + 文档 + 测试证据；
- 禁止越权/越界修改；冲突用任务板协调。

## 16. 工业化路线（阶段目标）

| 阶段 | 版本 | 目标 |
|---|---|---|
| S0 演示可用 | 0.9.x | 能装、能进桌面、有日志 |
| S1 契约与门禁 | 0.10.x | API/配置契约、CI 门禁、文档基线、L0–L4 |
| S2 可验证与可复现 | 0.11.x | A/B+签名+dm-verity+可复现+SBOM |
| S3 可运维与安全审计 | 0.12–0.14 | SLO、runbook、渗透/审计、隐私合规 |
| S4 LTS 与企业 | 0.15–1.0 | 兼容承诺、企业部署、长期支持 |

每个阶段结束做一次“工业化评审”，逐条核对第 1 节 10 条标准。
