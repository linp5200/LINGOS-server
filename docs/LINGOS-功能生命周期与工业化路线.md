# LING OS 功能生命周期与工业化路线

> 版本：v1（2026-10-30）
> 作用：规定“一个新功能从想法到上线到下线”的完整流程，并对后续可能产生的功能给出实施框架；
>       同时给出 0.9 → 1.0 的工业化阶段目标。

---

## 1. 功能生命周期（每个功能必须走完）

阶段 0：需求
- 用户问题、使用场景、优先级、不做的理由
- 产出：Issue/需求卡（目标、范围、验收标准）

阶段 1：方案
- 涉及架构/安全/隐私/接口时写 ADR
- 产出：ADR + 技术方案（组件、接口、数据、依赖、风险）

阶段 2：规格
- UX 规格（界面/交互/错误提示）
- 接口规格（API/事件/配置 schema）
- 安全/隐私规格（威胁、权限、数据流、默认值）
- 产出：规格文档 + 契约草案

阶段 3：实现
- 分支开发 + 单元/契约测试
- Feature flag 控制（默认关闭或灰度）
- 产出：代码 + 测试 + 文档

阶段 4：验证
- 集成/系统/安全/隐私/性能测试
- 真机或目标环境验证
- 产出：测试报告

阶段 5：发布
- 版本规范、CHANGELOG、升级说明、回滚方案
- 灰度/分批发布（1.0 前手动）
- 产出：Release + 文档

阶段 6：运维
- 指标/日志/告警/runbook
- 用户反馈与缺陷修复

阶段 7：演进/下线
- 兼容承诺、弃用通知、迁移工具、移除

每个阶段的“完成定义”（DoD）必须写清楚，不允许跳阶段直接上线。

---

## 2. 功能工业化的通用要求

1. 接口先于实现（契约测试）；
2. 默认值有安全/隐私评审；
3. 失败路径有错误码、用户提示、日志；
4. 可观测（指标/日志/trace）；
5. 可回滚（配置/数据/版本）；
6. 文档齐全（用户/管理员/开发）；
7. 测试覆盖正常/边界/攻击场景；
8. 资源预算（CPU/内存/体积/启动时间）；
9. 依赖可替换（不绑死第三方）；
10. 隐私影响评估（采集/存储/上报）。

## 4. 工业化阶段路线

### S0 演示可用（0.9.x）
- 能安装、能进桌面、无信号有 VNC/文本兜底
- 日志/诊断可获取
- 关键 bug 有回归用例
- 完成标准：Vectras 真机全流程通过

### S1 契约与门禁（0.10.x）
- API/IPC/工具/插件契约文档化，CI 契约测试
- 质量门禁上线（lint/build/test/boot smoke/security/隐私/文档）
- L0–L4 与本地配置通道
- 完成标准：main 每次合并全绿；0.10 发布包含契约文档

### S2 可验证与可复现（0.11.x）
- 签名启动、dm-verity、A/B、防回滚
- 可复现构建、SBOM、签名发布
- 完成标准：同 commit 重建 hash 一致；篡改包被拒

### S3 可运维与审计（0.12–0.14）
- SLO/SLI、告警、runbook、事故流程
- 渗透测试、隐私合规、CIS/OpenSCAP
- 完成标准：安全审计报告 + 运维演练通过

### S4 LTS 与企业（0.15–1.0）
- API/配置稳定性承诺、长期支持、企业部署/镜像站
- 完成标准：1.0 发布 + 兼容矩阵 + 支持生命周期

## 5. 工业化 KPI（每阶段评估）

- CI 通过率 ≥ 95%（main）
- 构建耗时/失败率趋势
- 测试覆盖率（核心模块）
- 每版本回归缺陷数
- 安装成功率（CI + 真机）
- 桌面启动成功率（含兜底）
- 安全高危漏洞数 = 0（发布前）
- 文档与代码一致性检查通过率
- 可复现构建一致率（0.11+）
- 用户反馈平均修复时间

---

## 6. 质量门禁与评审角色

- 功能评审：Lead + 相关模块负责人
- 安全评审：涉及认证/加密/网络/沙箱/更新/权限
- 隐私评审：涉及采集/位置/生物特征/云端 AI
- 发布评审：版本规范检查清单 + 测试报告
- 工业化评审：每阶段按第 5 节 KPI 复盘

---

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 功能膨胀导致质量下降 | 每版本功能预算 + 优先级评审 |
| 安全/隐私影响可用性 | 兼容性提示 + 单点放宽 + 默认 L1 |
| 硬件差异（无 TPM/KMS） | 显式降级与提示，不虚假承诺 |
| 构建/发布不可复现 | 固定工具链、容器化、SBOM |
| 文档过期 | 文档门禁 + 每版本扫描 |
| 子智能并行冲突 | 任务板写范围 + 单写入者 |
